## Performance evidence from the saved `oneios-perf.txt` excerpt

The user supplied an excerpt (140 lines after filtering, rather than the complete session logs); its display portion is **40 reporting windows totaling 200.758 s**, not the entire 600-second run.

- The display helper reported **2,135 posted SurfaceFlinger buffers**, weighted **10.63 posts/s**, median window rate **9.82 posts/s** and peak **40.33 posts/s**. **11/40 windows had zero posts**, including a contiguous gap of about 45 s. A zero-post interval can be an idle/static guest; posted-buffer rate is **not** rendered animation FPS or proof of a 10-Hz frame cap.
- The excerpt reports `full_copies=posts` in every window. At 1080 x 2340, full-buffer copying costs mostly **~1–2 ms p95**, with some multi-ms outliers. Copying wastes bandwidth but does not explain multi-second no-frame intervals by itself.
- The real **KGSL/drm2kgsl 3D path was active**, not an all-2D fallback: captured guest GPU contexts and blobs, KGSL-imported memory and a retired `backboardd` fence (one fence in one 52 s report; mean 988 us). This **does not** prove Vulkan API conformance, sustained 3D throughput or 60 Hz UI.
- Guest RAM was **4096/4096 MiB prefaulted and mlocked**, with **0 MiB guest swap**; Linux host swap usage (706 MiB in samples) is a different quantity. The guest page-table footprint was large (e.g. 371/378 MiB in samples); `ShmemPmdMapped=0` in the excerpt is an observation, not a safe reason to change global hugepage settings.
- Full-run host emulation counters: **21,536,983 traps at 35,862/s**, **10,981,111 syscalls**, **10,171,366 faults**, **384,506 interrupts**. Up/down trap handoffs averaged **21.68 / 20.84 us** (p99 **114.69 / 114.69 us**). Kernel syscall/fault p99 **655.36 / 524.29 us**, and rare max times ~3.03 s syscall / ~11.88 s interrupt. These are sampled lifetime outliers, **not a proven correlation with a specific touch gesture**.
- `Spotlight` repeatedly appeared at **~98–102% of one vCPU** in 10 s samples. Backboardd, SpringBoard, `healthd`, keyboard and other guest services added load. The cause (fresh Data indexing, guest ABI issue, scheduler overhead or a combination) is not yet isolated.
- The CPU mask `0-7` is **permission to execute on eight host CPUs**, **not proof of eight distinct vCPU-to-host-core pinning**. The full-run invocation uses `--mode bench` and `--set bridges=0`; general CPU topology/placement and the OneiOS thermal bridge are not initialized on that path. The phone's **kernel/firmware thermal protections still exist**, but no time-aligned thermal or cpufreq traces accompany this excerpt.

**User observation:** UI was noticeably laggy and the phone became very hot. There is no measured surface/skin or SoC temperature in this excerpt; do not claim a thermal threshold was crossed or use firmware thermal limits as an optimization knob.

## Current safety gaps — block another long full takeover

1. **P0 thermal:** Independent read-only thermal telemetry and a bounded, fail-safe heat-response policy for this **bench/bridges=0** path; never enable all hardware bridges to solve this. Verify actual sensor availability, unit conversion, unknown-sensor handling and return interaction with existing watchdog/deadline. Do not assume the thermal policy from `bridges=1` protects this run.
2. **P0 recovery:** Correlate original `return.outcome`, `return.log`, watcher/feeder logs and final host timeline after root is regained **read-only**; establish precise 600-second requester and unassisted path separately from `ro.boot.bootreason`. The watchdog device/driver/timeout remains `UNVERIFIED_REBOOT_ONLY`.
3. **P0 telemetry:** Preserve per-run GPU/CPU/display/thermal evidence across root loss using rootless host receipts and root-owned device archives; prevent untrusted or stale session logs from being mistaken for the new run.
4. **P1 CPU:** Profile syscalls, page faults, futex/host handoffs and the worst latency outliers; investigate Spotlight and first-launch cache/index workloads before disabling any guest daemon.
5. **P1 placement:** Evaluate isolated, opt-in 8-vCPU host affinity/placement with local CI and short, matched A/B sessions first; preserve the full-run safety gate and never force host governor, uclamp or cpufreq ceilings.
6. **P2 GPU:** Verify context/fence/thermal measurements across interactive periods, GPU blobs/import lifetime, and guest Vulkan capability separately from `gpu=auto` initialization.
7. **P2 display:** Correlate guest damage/flush, compositor fence and helper post gaps; avoid calling posts-per-second animation FPS. Explore partial dirty rectangles and only later zero-copy if technically safe.
8. **P3 memory:** Investigate page tables and SHMEM THP behavior read-only; no global sysctl or hugepage policy change without proof and a rollback strategy.
9. **P3 acceptance:** Reproducible short-session CPU/GPU/thermal and touch-to-frame p50/p95/p99 benchmarks; then local CachyOS CI and controlled risk-assessed device verification. No unproven “smooth 60 fps” or “production-safe” claim.

**Source changes (not yet on-device accepted):** the isolated OneOS CPU90 branch now uses `birth $$`, a passive `--pid-birth-selftest` before APFS consumption, an on-phone pre-rearm selftest in its host wrapper, a targeted regression checking PID syntax and a fail-fast error when the guard cannot arm.
